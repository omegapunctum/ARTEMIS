# ARTEMIS — локальный редактор знаний

Редактор запускается отдельным локальным backend. Он сохраняет черновики, редакционные решения и опубликованные карточки в постоянную SQLite-базу. Публичный глобус на GitHub Pages не принимает эти записи: размещение backend в интернете пока не настроено. Карточка, «опубликованная» при локальном запуске, доступна без входа на этом локальном сервере, а не всему интернету.

Контракт пилота: [Knowledge Editor v1](work/2026-10-07_KNOWLEDGE_EDITOR_v1.md). Редакционное принятие сохраняет статус утверждения, источника и доказательной связи `draft`, а состояние доказательств — `missing`. Оно не подтверждает историческую достоверность и не добавляет запись в корпус глобуса или Airtable.

## 1. Подготовка и запуск

Нужны Python 3.11 и локальный checkout ARTEMIS. Команды ниже предназначены для Bash на Linux/macOS; выполняйте их из корня репозитория. Каталоги окружения и рабочих данных размещаются вне checkout.

```bash
python3 -m venv "$HOME/.local/share/artemis-editor-venv"
"$HOME/.local/share/artemis-editor-venv/bin/python" -m pip install -r requirements.txt
"$HOME/.local/share/artemis-editor-venv/bin/python" scripts/run_knowledge_editor.py \
  --data-dir "$HOME/.local/share/artemis-editor" \
  --owner-email owner@example.com
```

`owner@example.com` — пример, замените его адресом своего локального аккаунта. Этот адрес определяет, какой аккаунт имеет права редакционной проверки и публикации. Скрипт не создаёт аккаунт и не назначает пароль. Другие зарегистрированные аккаунты получают обычные права автора; выбор адреса в конфигурации — действие оператора сервера, а не настройка пользователя в форме.

Откройте **http://127.0.0.1:8000/editor/**. Введите свой адрес и пароль, затем нажмите **«Создать аккаунт»**. При последующих запусках используйте **«Войти»**. Пароль задаётся в интерфейсе, а не в командной строке. Если аккаунт уже существует, повторная регистрация не нужна.

Для другого свободного порта добавьте, например, `--port 8001` и откройте адрес, напечатанный скриптом. Сервер слушает только `127.0.0.1`; этот способ запуска не открывает редактор другим устройствам. Производственный хостинг, HTTPS и настройка сессий для нескольких процессов требуют отдельного развёртывания.

## 2. Одна запись от черновика до публикации

1. Нажмите **«Новый объект»**, укажите название архитектурного объекта и нажмите **«Сохранить черновик»**. Источник и утверждение можно заполнить позже. Сообщение **«Черновик сохранён на сервере»** появляется после успешного ответа backend; текст, просто введённый в форму, ещё не сохранён.
2. Выберите запись в **«Мои записи»**. Заполните название источника, ссылку **или** библиографическое описание, одно утверждение, точное место в источнике и исходную формулировку. Автор, права, дата или местоположение могут оставаться неизвестными. Точные координаты и даты для этого пилота не нужны.
3. Укажите характер утверждения, отношение источника к нему и известные ограничения. Уверенность по умолчанию не определена; для другой оценки нужно записать её основание. Подтвердите самостоятельное авторство: AI-предложения не принимаются этим пилотом.
4. Сохраните изменения, затем нажмите **«Отправить на проверку»**. Отправляется точная сохранённая версия. После отправки текст нельзя менять в обход решения проверяющего.
5. Аккаунт, заданный через `--owner-email`, видит **«На проверке»** и раздел **«Редакционная проверка»**. Откройте источник, проверьте утверждение и locator, введите основание решения. Доступны **«Принять редакционно»**, **«Запросить исправления»** и **«Отклонить»**. Если автор и проверяющий — тот же аккаунт, система явно отмечает **«Проверка автором записи»** (`owner_self_review`). Это не независимая проверка. Проверка другим аккаунтом также не доказывает независимость людей или компетентность проверяющего.
6. После принятия нажмите отдельно **«Опубликовать карточку»**. До этого действия принятие не делает запись публичной. Откройте **«Открыть опубликованную карточку»**: карточка показывает утверждение, источник и locator, неопределённость, режим проверки и сведения о версии. Приватный исходный фрагмент источника в неё не включается.

Ссылку на карточку можно открыть в приватном окне браузера без входа, пока локальный сервер работает. Её адрес имеет вид `/editor/?object=<ID>`; конкретная неизменяемая публикация — `/editor/?snapshot=<ID>`. Копируйте фактическую ссылку из интерфейса, а не придумывайте идентификатор.

## 3. Исправление с сохранением истории

Откройте принятую запись, заполните **«Почему нужна поправка?»** и нажмите **«Создать черновик исправления»**. Измените кандидатное утверждение и его основание, повторно подтвердите авторство, сохраните и отправьте на проверку. Редакционное принятие поправки создаёт новую принятую версию. Публикация этой версии снова требует отдельного действия.

Старая принятая версия не изменяется. До публикации поправки ссылка объекта показывает прежнюю опубликованную карточку; после публикации — новую. Ранее опубликованные версии остаются в **«История публикаций»** и доступны по своим ссылкам. Приватная **«История записи»** содержит действия и основания решений; она не публикует заметки проверяющего.

При конфликте версий интерфейс сохраняет введённый текст и предлагает загрузить актуальную версию сервера. Скопируйте нужные изменения перед заменой формы. При обрыве связи или истечении сессии не считайте ввод сохранённым до подтверждения backend; войдите снова и повторите сохранение. Закрытие вкладки может потерять несохранённый текст.

## 4. Где лежат данные

В каталоге `--data-dir` хранятся:

- `editor.sqlite3` — аккаунты и хеши паролей, приватные черновики и исходные фрагменты, редакционные события, принятые версии и публичные снимки;
- `auth-secret.key` — автоматически созданный постоянный секрет подписи токенов;
- дополнительные файлы SQLite, если их создаёт работающая база; существующий backend также может создать каталог `uploads`, но загрузка файлов не является функцией этого редактора.

База и исходные фрагменты не шифруются самим приложением. Держите рабочий каталог и резервные копии в приватном месте, вне Git, публичных файловых каталогов и общих папок. Скрипты создают новые каталоги/файлы с ограниченными правами; права уже существующих каталогов нужно проверить отдельно. Не публикуйте базу, секрет, пароли, токены, реальные адреса аккаунтов или приватные цитаты в репозитории и журналах задачи.

Остановите сервер через `Ctrl+C`. Для продолжения выполните ту же команду с прежним `--data-dir` и адресом владельца. Сохранённые записи остаются в базе. Сессии этого локального режима хранятся в памяти, поэтому после перезапуска может потребоваться повторный вход. Не удаляйте и не заменяйте рабочую базу или секрет ради устранения ошибки входа.

## 5. Резервная копия и восстановление

Скрипт резервирования использует SQLite backup API и проверяет целостность исходной и скопированной базы. Он может делать согласованную копию работающей базы; не заменяйте это простым копированием одного открытого `.sqlite3` файла, которое может пропустить данные журнала.

Из корня checkout:

```bash
python3 scripts/knowledge_editor_backup.py backup \
  --source "$HOME/.local/share/artemis-editor/editor.sqlite3" \
  --destination "$HOME/.local/share/artemis-editor-backups/first-backup.sqlite3"
```

Назначение должно быть **новым файлом**. Скрипт не перезаписывает существующие файлы: для следующей копии выберите другое имя. Успех сопровождается сообщением о проверке целостности и SHA-256 копии. Сохраните резервную копию в приватном хранилище, желательно также на отдельном устройстве; сам скрипт не настраивает автоматическое резервирование или удалённое хранение. `auth-secret.key` не входит в копию базы: при резервировании рабочего окружения храните его отдельно и приватно, не выводя содержимое в терминал или отчёт.

Для пробного восстановления используйте **новый каталог**, не рабочую базу:

```bash
python3 scripts/knowledge_editor_backup.py restore \
  --source "$HOME/.local/share/artemis-editor-backups/first-backup.sqlite3" \
  --destination "$HOME/.local/share/artemis-editor-restored/editor.sqlite3"
"$HOME/.local/share/artemis-editor-venv/bin/python" scripts/run_knowledge_editor.py \
  --data-dir "$HOME/.local/share/artemis-editor-restored" \
  --owner-email owner@example.com \
  --port 8001
```

В новом каталоге скрипт запуска создаст новый секрет; старые токены не переносятся. Войдите прежним сохранённым аккаунтом и паролем, проверьте список записей, обе публикации и историю исправления. Это восстановление копии, а не замена рабочих данных. Команды не перемещают источник и не удаляют старое окружение.

Резервирование здесь охватывает SQLite-базу пилота. Оно не является резервированием всех файлов прежних backend-функций, не доказывает production disaster recovery и не переносит данные в PostgreSQL/PostGIS или S3.

## 6. Перенос опубликованной карточки

В опубликованной карточке нажмите **«Скачать опубликованную историю (JSON)»**. Файл содержит все опубликованные версии этого объекта на момент скачивания, включая прежние карточки. При открытии старой версии действие всё равно скачивает текущую опубликованную историю объекта. Приватные черновики, принятые, но ещё не опубликованные версии, исходные цитаты, заметки проверяющего, аккаунты и секреты в файл не входят. Ссылки и библиографические сведения остаются частью опубликованных карточек; сами внешние документы не скачиваются.

JSON-пакет сохраняет идентификаторы, locator, неопределённость и режим редакционной проверки. Его SHA-256 позволяет проверить внутреннюю целостность; он не доказывает подлинность отправителя, достоверность источника или историческую проверку. Ссылка на предшествующую принятую версию может не иметь опубликованной карточки: такой разрыв отмечается явно и не заполняется приватными данными.

Для проверки скачанного файла из корня checkout:

```bash
"$HOME/.local/share/artemis-editor-venv/bin/python" scripts/verify_knowledge_editor_export.py \
  /path/to/artemis-editor-object-public.json
```

Замените путь фактическим именем скачанного файла. Проверка выполняется локально, без открытия ссылок, импорта или изменения базы. Она проверяет формат, хеши и согласованность ссылок; она не может независимо доказать, что отправитель включил все существующие публикации. Успешный экспорт и входной файл ограничены 32 MiB; при превышении экспорт отказывается целиком, без обрезания истории.

Этот файл предназначен для выборочного переноса опубликованных карточек. Для восстановления приватного рабочего окружения используйте резервную копию SQLite из раздела 5. Импорт пакета и добавление его данных в глобус пока не реализованы. [Контракт экспорта](work/2026-10-07_EDITOR_PUBLIC_EXPORT_v1.md) фиксирует техническую границу; фактическую готовность проверяйте в `PROJECT_TRUTH.md`.
