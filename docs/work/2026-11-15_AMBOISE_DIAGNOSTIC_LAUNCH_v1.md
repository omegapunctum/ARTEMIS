# Amboise: launch decision for one comprehension session

Status: conditional launch scope independently reviewed; session NOT RUN / observations NOT COLLECTED. Class: DECISION for a bounded diagnostic, with no product or gate transition. The owner requested continued autonomous work towards a fully working project; this proposal applies that direction to the next unresolved question in the [roadmap](2026-11-01_ARTEMIS_OUTCOME_AND_ROADMAP_v1.md).

## Question and choice

Can an independent newcomer use the public Explorer, without hints, to locate the Amboise baptism context, explain what the shared place and year do and do not establish, and find the source and date uncertainty? Choose one observed session with the existing [protocol v1](amboise_comprehension_v1/README.md). Another UI revision would assume where the difficulty lies; adding a second case would add curation and review before observing the first; a map-versus-text comparison requires a separate matched protocol. All three alternatives remain deferred.

One consenting adult unfamiliar with the implementation; one Russian-language session; one fixed public Explorer build; five tasks from protocol v1. The scope is the currently available 2D path through Clos Lucé, not an evaluation of Globe or a claim about all users. No outreach or collection through tooling, personal details, recordings, public raw responses, new runtime work or Gate E reopening.

## Launch conditions and acceptance

1. Confirm [PR #489](https://github.com/omegapunctum/ARTEMIS/pull/489) has passed review and been merged and that a separately verified deployment includes its changes. Record the protocol commit and the `release_provenance.source_commit`, `workflow_run_id`, and `workflow_run_attempt` from `/ARTEMIS/globe/build-meta.json`. A numbered PR or passing pre-merge check cannot identify what a participant saw.
2. In a separate preflight window use the protocol's published start URL. Confirm the starting presentation has the Clos Lucé card, that its existing details show context at 1518, that 1517 and 1519 remove the context while retaining the residence, and that returning to 1518 restores the context and its source links. Give the newcomer a fresh private browser window at the start URL, with no preflight controls or answer sheet visible. Check release identity immediately before starting and after the session. If delivery, identity or the starting state cannot be verified, record a blocker and do not collect responses. A change or unconfirmed identity found afterwards makes affected observations inconclusive.
3. Arrange one volunteer independently and record consent in the private working copy of the template. Show the participant only [the task sheet](amboise_comprehension_v1/participant_tasks.md). Apply the existing [rubric](amboise_comprehension_v1/observer_reference.md); distinguish first unaided responses from assisted ones. Keep raw observations private and persist only a separately reviewed anonymized finding, if any.
4. Stop after one session and one interpretation, or before collection if a launch condition fails. Classify the first observed obstacle and choose at most one bounded next proposal. If all tasks pass unaided with no critical error, a matched comparison may be proposed separately. No result from one session validates comparative or formal user value.

A browser screenshot or AI walkthrough can serve step 2 only. Neither is a participant observation.
