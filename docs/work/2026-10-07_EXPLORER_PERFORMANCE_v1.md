# Explorer loading and movement performance v1

Status: bounded implementation / exact-head measurement and review pending.

Authority: the owner's 2026-10-05 request to resolve globe loading/interaction stalls and 2026-10-07 continuation. Classification: REVIEW under the existing [unified workspace specification](2026-10-05_UNIFIED_LAYER_EXPLORER_v1.md) and DOS §6. No new product gate or historical-data decision is needed for these behavior-preserving changes. The accepted Cesena correction proposal is a separate knowledge task; it is not implemented by this performance change.

Baseline: main `76404197f5e37192ce8d18c61d3d039af946fac0`. The 1,743,666-byte bundle is already minified. A 200-iteration Node diagnostic measured parse+recursive freeze median 16.75 ms / p95 28.15 ms, query approximately 0.004 ms and feature construction approximately 0.030 ms. These are host-specific CPU measurements, not browser/device measurements or a cause attribution for the owner's stalls. The initial multi-second network sample is likewise insufficient to identify a user-device bottleneck.

The baseline waits for engine download before starting four uncached JSON requests, repeatedly interleaves label size reads and position writes on map movement, and formats large source-native JSON while its disclosure is closed. The bounded correction preloads the two heavy data resources while the engine loads; pins reusable data, runtime and CSS URLs to their exact content SHA-256; permits normal HTTP caching for those heavy payloads while revalidating metadata; batches label measurements before writes and coalesces movement/hover work to one callback per frame; and formats raw JSON only upon opening its existing disclosure. All native data, coordinates, identities, query semantics, map/document persistence, selection, collisions, disclosures and chronology policies remain unchanged. The external pinned MapLibre CDN dependency remains; complete elimination of network/device/GPU stalls is not claimed.

Owned scope: unified builder/runtime/template; focused tests; paired CDP performance runner and Core CI wiring; completed #470 lifecycle documentation. The runner uses the exact baseline template/runtime/CSS, identical bundle bytes and three alternating baseline/current pairs. It measures cold/warm resource transfers, readiness, 160 frame-spaced camera movements and CDP layout/style counts, plus collapsed Region selection and keyboard-opened raw input equality. Local max-age=3600 caching is controlled evidence, not Pages caching proof; software WebGL and programmatic movement do not establish real-device FPS or native gesture usability. Local Chromium cannot launch because the executor denies its process-singleton socket; actual browser evidence must come from CI.

Acceptance: focused regressions, current Core checks, independently inspected exact-head code/native desktop/narrow evidence, same disclosed raw-input digest, unchanged bundle and a measured reduction of the targeted unnecessary work. Keep noisy timings and negative findings visible; do not turn a lab timing into a production SLO. After expected-head merge, separately verify Pages source/run identity, every-file live bytes and live native behavior. Stop after this complete performance release; no broad renderer rewrite, new backend, corpus intake or automatic successor is opened.
